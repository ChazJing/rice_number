# 稻粒 · 水稻种子计数

专用于**平铺水稻种子**的中文网页工具。手机拍照或选图 → 服务器识别 → 每粒种子标一个红点 → 人工补点、删点 → 按最终红点数量计数。

**识别在服务器 CPU 上运行。手机和电脑只做照片显示、交互和文件导出，不运行识别模型。上传图片不保存到服务器磁盘，处理完成后立即清理，无须等下一张。**

本仓库包含可运行的前端、识别 API、测试、Docker 配置和 Nginx 示例。它需要部署到支持 Python 或 Docker 的服务器；GitHub 用来保存代码，GitHub Pages 无法单独运行这个后端。

## 已实现

- 手机拍照/相册选择，电脑选图；中文响应式界面。
- 白纸背景局部光照校正，兼顾一般阴影；可切换自动、深色和普通浅色背景。
- 连通区域检测和距离变换分水岭，尝试分离粘连种子。
- 红点叠加、黄色复核外圈、放大缩小、拖动查看、隐藏标点。
- 点击补点、删点、撤销；键盘撤销和精确坐标补点/编号删点。
- 数量始终取当前红点数组长度，人工修正后即时更新。
- 人工确认结果；导出标记 JPG 和包含原图坐标、数量、识别设置的 JSON。
- 浏览器仅保留最近两张照片；第三张替换最早的一张，可随时清空。
- 20 MiB 上传和 2400 万像素限制，单次只处理一张，繁忙时返回提示。
- 可选服务器访问口令；网页不包含第三方脚本、分析 SDK 或外部服务调用。

## 精度边界

第一版是**针对拍摄条件的图像处理算法**，不是已用你的真实照片训练的水稻神经网络。自动标记需要人工复核。当前的模拟照片测试不能证明真实照片达到某个准确率。

建议拍摄带壳水稻种子：白纸铺底，种子尽量分开、平铺、不堆叠，照片四周留一圈空白。默认“白纸背景 · 阴影校正”会估计局部纸面亮度，减少大片灰色阴影的影响。严重硬阴影、纸张褶皱、低对比浅色种子、模糊、杂物、芒、紧密粘连和遮挡仍可能造成漏检或误检。完全被其他种子挡住的种子无法从单张照片确认。

水稻是目标材料，但本算法不是物种分类器，不能保证自动排除纸上的碎屑、杂草种子或其他形状相近的东西。不提供实粒/空粒判断、重量或品种判断。

后续应使用实际照片和人工真值评估：不仅比总数，还检查每粒种子是否恰好有一个红点，防止漏检与误检相互抵消。见 [验证记录与真实照片评估](docs/VALIDATION.md)。

## 启动（开发或本机验证）

需要 Python 3.12，建议 Linux x86_64 或 ARM64、至少 1 GB 内存，2 GB 更宽裕。识别速度需在你的两核服务器上实测。

```bash
git clone https://github.com/ChazJing/rice_number.git
cd rice_number
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 uvicorn backend.app:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

打开 `http://127.0.0.1:8000`。这只是本机入口。手机访问需要后续配置服务器的域名、反向代理和 HTTPS；不同手机浏览器的拍照入口存在差异，可用“选择照片”作为备用入口。

## Docker 部署准备

```bash
cp .env.example .env
# 在 .env 中填写 RICE_ACCESS_TOKEN（如需限制访问）
docker compose up -d --build
```

默认仅绑定服务器的 `127.0.0.1:8000`，容器最多使用两核和 768 MiB，应用文件系统只读。用 [Nginx 示例](deploy/nginx.conf.example) 代理整个网站，并配置 HTTPS。Nginx 必须保持 `proxy_request_buffering off`，否则可能把上传图片缓冲到磁盘。

完整准备和注意事项见 [部署说明](docs/DEPLOYMENT.md)。本次代码交付不会自动修改你的服务器。

## 使用

1. 选择/拍摄照片，点击“开始识别”。支持 JPG、PNG、WebP；iPhone HEIC 请改用“兼容性最佳”拍照格式，或另存为 JPG。
2. 放大查看，黄色外圈优先检查。所有种子仍需目视复核。
3. 默认“修正”模式：点空白补点，点已有红点删除。也可以分别使用“补点”“删点”。
4. 检查完成后，点击“我已检查，确认这个数量”，再导出标记图和计数数据。
5. 最近两张之间可以切换；第三张会释放最早一张的页面引用。清空/关闭页面后不保留照片或标记。需要保留研究记录时，请先主动导出。

重新识别会覆盖该照片当前的标记；有人工修改时，页面会提示确认。上传失败不会清空已有标记。客户端取消请求时，服务器可能已开始计算，仍会在计算结束后清理，然后才接收下一次识别。

## 隐私与内存

上传使用原始二进制请求，**不使用容易产生临时文件的 multipart 上传**。服务器流式读入有大小限制的内存缓冲，照片解码、校正、分割均在内存中进行，只返回红点坐标和文本。成功、图片错误、上传失败均清理缓冲；处理中的请求取消也不会遗留长期任务或照片记录。

浏览器不使用 localStorage、IndexedDB、Service Worker 或服务器相册保存照片。最近两张保留在页面内存中，淘汰时撤销 Object URL 并释放 File/图像/标点引用；关闭或离开页面会清空。主动导出的文件由用户保留，原有相册照片也不会被删除。

“释放”指移除程序引用，让内存可复用。Python/浏览器可能保留已经申请的内存页，所以任务结束后的进程内存数字不一定立即下降；这不意味着程序还保留可再次访问的照片。这里不承诺内存逐字节安全擦除，也不控制操作系统交换区或其他未采用示例配置的中间代理。具体保证见 [架构与数据生命周期](docs/ARCHITECTURE.md)。
