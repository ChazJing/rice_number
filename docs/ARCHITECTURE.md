# 架构与数据生命周期

```text
手机 / 电脑浏览器                    两核服务器
选择照片，保留当前页面 File          提供 HTML / CSS / JS
          ── POST 图片二进制 ──→     上传内存缓冲（最多 20 MiB）
                                   Pillow 读取并按 EXIF 转正
                                   缩小工作图（最长边 2200 px）
                                   白纸局部光照校正 / 背景分割
                                   去噪、连通区域、粘连分水岭
          ←── JSON 红点坐标 ──      返回原图坐标，清理图片引用
原照片叠加红点
人工修正、计数、导出
```

浏览器对图像进行显示和导出绘制，但不执行识别。服务器只保留处理中的任务，没有数据库、图片目录、相册或历史图片读取接口。

## 识别方法

- 工作尺寸上限 2200 px；返回坐标按 EXIF 转正后的原图宽高缩放。
- 默认白纸：灰度闭运算估计局部纸面光照，按局部亮度校正，并结合种子颜色差异。
- 自动背景：明亮近中性的纸面也走光照校正；其他背景按边缘中位颜色距离分割。
- 阈值用 Otsu 加灵敏度偏移，接着中值去噪、开运算和孔洞填充。
- 小连通区域按图像面积比例过滤；过大区域排除并提示。
- 凸形细长种子不强行分离；凹形粘连候选用平滑距离变换峰值作为分水岭标记。
- 对分离候选和边缘种子加复核标记，不输出未经校准的概率或“准确率”。

## 清理行为

| 情况 | 服务器 | 浏览器 |
|---|---|---|
| 识别完成 | 释放图像局部引用，清空上传缓冲 | 保留本张照片与红点 |
| 非法图片或算法异常 | 清理缓冲，释放任务槽 | 显示错误，保留已有标记 |
| 上传超过限制/超时/中断 | 清理已收字节，释放任务槽 | 显示错误 |
| 客户端取消识别 | 已开始的线程完成后清理，期间保持繁忙 | 忽略过期响应 |
| 下一张照片 | 原图早已清理 | 保留最近两张 |
| 第三张照片 | 无图片历史 | 淘汰最早一张并释放页面引用 |
| 清空/离开页面 | 不需要专门删除接口 | 撤销图片 URL，移除照片、图像与历史引用 |

单 worker、单任务槽是两核机器的有意限制；不要增加 Uvicorn workers，否则每个 worker 都可能各处理一张，增加峰值内存。识别在线程中执行，健康检查仍可响应。繁忙请求返回 429，不在应用内排队保存照片。

## 部署边界

需要确保反向代理也不把请求正文写磁盘，不启用图片请求正文日志，不加入 CDN 图片缓存、APM 正文采集或外部识别服务。应用响应使用 `Cache-Control: no-store`。

Docker 示例限制写权限并禁用 core dump。程序层面不写图片；如果需要更严格的基础设施隐私，要另外检查宿主机的交换区、崩溃采集和代理配置。进程内存页的复用不等于可恢复的应用图片记录。

访问口令为可选部署参数 `RICE_ACCESS_TOKEN`。服务端用恒定时间摘要比较，浏览器只在当前页面保留用户输入的口令。应使用 HTTPS，口令不会放进请求 URL。
